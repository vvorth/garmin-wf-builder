# Probe: what does a repeated primitive cost, baked or looped?

**Answer: a runtime loop is 7–30x cheaper than baking the copies, and its
cost does not grow with the copy count.** Measured with `monkeyc
--build-stats 0`, `-w`, `--no-gen-styles`, the generated jungle's `-O 3z`,
on `fenix8solar47mm`, SDK 9.2.0, 2026-09-14. All builds `BUILD
SUCCESSFUL` and warning-free. Backs plan 05 §2 (patterns).

## Why this was asked

A pattern — 60 minute ticks, 12 hour ticks, a segmented ring — is one
template drawn N times. There are three ways to get it onto the watch, and
ADR 0004 prefers the first: nothing relative reaches the device.

1. **Bake N elements.** Expand the pattern into N ordinary `shape`
   elements at build time. Every copy's pixels are a `Layout` constant.
   Needs no new codegen at all.
2. **Bake one array, loop over it.** Resolve every copy's pixels at build
   time into one flat `Layout` array constant, and draw it with a loop.
3. **Loop and transform at runtime.** Resolve the *template* at build time
   (as analog hands already do) and let the watch rotate or translate it
   once per copy, with `Math.sin`/`Math.cos`.

## What was built

A base face (`static:` background, one line tick, a `time.clock` text) was
generated by `wfb build`; each variant then added one method,
`drawPat(dc)`, called from `drawStatic`, plus its `Layout` constants.
Variant 1 was generated by `wfb build` itself from faces with N
`shape: line` elements.

Variant 2, 60 lines (`PAT_LINES` is 240 `Number`s, four per line):

```monkeyc
private function drawPat(dc as Dc) as Void {
    dc.setColor(Palette.FG, Graphics.COLOR_TRANSPARENT);
    dc.setPenWidth(Layout.PAT_THICKNESS);
    var a = Layout.PAT_LINES;
    for (var i = 0; i < a.size(); i += 4) {
        dc.drawLine(a[i], a[i + 1], a[i + 2], a[i + 3]);
    }
    dc.setPenWidth(1);
}
```

Variant 2 for polygons: `const PAT_POLYS as Array<Array<Graphics.Point2D> >`
holding 12 four-vertex polygons, drawn by `fillPolygon(a[i])` in a loop.

Variant 3, 60 lines, with a skip test (`Layout.PAT_X1`… are the template
line's ends in a frame whose origin is the centre):

```monkeyc
private function drawPat(dc as Dc) as Void {
    dc.setColor(Palette.FG, Graphics.COLOR_TRANSPARENT);
    for (var i = 0; i < 60; i++) {
        if (i % 5 == 0 || i == 7) {
            continue;
        }
        var t = i * (Math.PI / 30.0);
        var s = Math.sin(t);
        var c = Math.cos(t);
        dc.drawLine(Layout.PAT_CX + Layout.PAT_X1 * c - Layout.PAT_Y1 * s,
                    Layout.PAT_CY + Layout.PAT_X1 * s + Layout.PAT_Y1 * c,
                    Layout.PAT_CX + Layout.PAT_X2 * c - Layout.PAT_Y2 * s,
                    Layout.PAT_CY + Layout.PAT_X2 * s + Layout.PAT_Y2 * c);
    }
}
```

## Findings

| variant | copies | data | code | total | added over the base |
|---|---|---|---|---|---|
| base face (1 tick element) | — | 598 B | 675 B | 1,273 B | — |
| 1: bake N elements | 12 lines | | | 2,201 B | +928 B (77 B a copy) |
| 1: bake N elements | 60 lines | | | 6,233 B | **+4,960 B** (83 B a copy) |
| 2: one flat array + loop | 12 lines | 875 B | 807 B | 1,682 B | +409 B |
| 2: one flat array + loop | 60 lines | 1,835 B | 807 B | 2,642 B | **+1,369 B** (~5 B a coordinate) |
| 2: array of `Point2D` arrays | 12 rectangles | 2,008 B | 1,239 B | 3,247 B | **+1,974 B** |
| 3: runtime rotation | 60 lines | 607 B | 836 B | 1,443 B | **+170 B** |
| 3: runtime rotation + skip test | 60 lines | 607 B | 857 B | 1,464 B | **+191 B** |

(Variant 1's rows are whole-face totals from `wfb build`, which reports the
sum only.)

1. **Baking copies as elements costs ~80 B a copy.** A 60-tick minute
   ring is 3.8% of the 131,072 B budget before anything else is drawn.
2. **A baked array costs ~5 B per coordinate**, because a Monkey C array
   literal is built by bytecode at module load and then held in data. It
   is linear in the copy count, just with a smaller slope.
3. **Nested `Point2D` arrays are the worst option** (+1,974 B for 12
   rectangles): the literal's construction code grows with every inner
   array.
4. **The runtime loop is flat: ~170 B whatever the count**, plus ~20 B
   for a skip test. Its cost is in time, not memory: one `sin`/`cos` pair
   and one draw call per copy per frame. For content in `static:` that is
   paid once, when the buffer is filled.
5. **`continue` inside a `for` loop compiles warning-free** under the
   generated project's settings.

What this does not measure: the CPU and battery cost of variant 3 on a
watch (there is no simulator or device in this container), and how the
firmware rasterises Float coordinates without anti-aliasing. Both are
shared with analog hands (`../analog-hands/`, finding 1) and recorded there
and in `docs/limitations.md`.
