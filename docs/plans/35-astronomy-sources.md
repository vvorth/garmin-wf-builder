# Plan 35 — astronomy sources: numeric month, UTC offset, position, `astro.*`

**Status:** in progress (2026-10-29). Decided by the user: slices A–D all
built, in this order, as the requirements below say. Delete this file when
the last slice ships (`docs/plans/README.md`).

## 0. Why

The Solaria face (`examples/generated_by_skill/solaria/`) showed what the
format cannot reach from YAML alone: a numeric month (it compares the
localised month name against English strings), the watch's UTC offset (its
second time zone is "an offset from local time"), the wearer's position
(no sun height, approximate sidereal time) and trigonometry (tables for the
equation of time and the declination). Each is a value the watch already
has or can compute in a few lines of Monkey C. ADR 0003 permits a small
hand-written barrel and ADR 0005 a typed catalogue; nothing here is an
interpreter, nothing branches on the design.

## 2. Slice A — `date.month_number`

| Path | Type | Reader | Read |
|---|---|---|---|
| `date.month_number` | number 1–12, not nullable | `date_short` (`Gregorian.info(Time.now(), Time.FORMAT_SHORT)`) | field `month`, `cast: "Number"`, exactly as `date.weekday` reads `day_of_week` |

- The name already exists as a *sample key* (`ts/src/sample.ts`,
  `dateValues` in `ts/src/preview.ts`, `%m` in `ts/src/formatting.ts`): make
  it a real catalogue source with the same name, so `--date` and `--sample`
  keep working. `doc`: "month as a number, 1 = January .. 12 = December";
  `source_ref`: `Toybox/Time/Gregorian.html`.
- `wfb sources` lists it; `{date.month_number:d}` and `{date.month_number:02d}`
  build; an expression `date.month_number > 2` type-checks.
- Test: an emitted view reads `dateShort.month as Number` (an `emit` test
  beside the one that holds `date.weekday`), and the preview renders the
  sample month (9) and a `--date 2026-02-14` month (2).

## 3. Slice B — `time.utc_offset`

| Path | Type | Reader | Read |
|---|---|---|---|
| `time.utc_offset` | number, seconds east of UTC, not nullable | `clock` (`System.getClockTime()`) | field `timeZoneOffset` (`Toybox/System/ClockTime.html`, API 1.0.0: "The time offset from UTC in seconds") |

- `doc`: "the local time's offset from UTC in seconds, as the watch reports
  it (DST included when in force)". Whether `timeZoneOffset` includes DST is
  not stated by the SDK: say so in `docs/guide/data.md` as UNVERIFIED, and
  that `time.utc_offset` is whatever `ClockTime.timeZoneOffset` holds.
- Sample value: `7200` (two hours east, the sample date is 3 September).
- Guide example (`docs/guide/data.md`, in the `time.*` material): UTC as
  `"{((time.hour * 3600 + time.minute * 60 - time.utc_offset) % 86400 + 86400) % 86400:%H:%M}"`,
  and a second zone at offset `O` seconds as the same with `+ O`.
- Test: emitted read `clock.timeZoneOffset`; the preview draws the UTC
  example as `08:09` at the sample 10:09 and offset 7200.

## 4. Slice C — the wearer's position, and the catalogue's `call:`

### 4.1 The mechanism: a source read through a barrel call

Today a source is a reader local's field (`catalog.readExpr`). A position
in degrees needs `weatherCurrent.observationLocationPosition.toDegrees()[0]`
turned into a `Float?`, and slice D needs values computed from two readers.
Add to `Source` (`ts/src/catalog.ts`, `ts/src/data/catalog.json`), both
optional with defaults so every existing entry is unchanged:

| Key | Meaning |
|---|---|
| `call` (string or null) | the barrel function the value is read through: `read = <call>(<reader local>[, <extra reader locals>…])` |
| `extra_readers` (string[], default `[]`) | further readers the call takes, in parameter order after the primary `reader` |

Rules:
- `ReadPlan` (`ts/src/emit/monkeyc/readplan.ts`) hoists every reader a
  source names (primary and extra) exactly as it hoists the primary today:
  `dedupeReaders`, `readersUsedBy`, `parameters`/`arguments`, and the
  per-mode reader lists. `Requirements.add` (`catalog.ts`) adds every
  reader's module. `sourceUnavailable` (`availability.ts`) checks the
  extra readers too.
- A nullable reader among the call's readers is guarded the way the
  primary already is (`reader != null`), and a module guard
  (`Toybox has :Weather`) is written where `device_guards.modules` says so;
  the barrel function then takes non-null parameters. The source itself is
  `nullable: true` when the call can return null.
- `field_name` stays the field the device-table check (`hasField`) is keyed
  on, so a device lacking `observationLocationPosition` gets the `api-gated`
  lint and a `has :observationLocationPosition` guard like any field.
- `barrelModules` (`ts/src/emit/usage.ts`) already copies a barrel file
  named in the generated source; `WfbAstro.mc` needs no registration.
- A test that a source with `call:` and one extra reader emits the call
  with both locals, hoists both readers, and guards the nullable one; and
  that every pre-existing source emits exactly what it did (the goldens).

### 4.2 The sources

| Path | Type | Reader | Read |
|---|---|---|---|
| `position.latitude` | float, degrees, + north, nullable | `weather_current` | `call: WfbAstro.latitude`, `field_name: observationLocationPosition`, `permissions: ["Positioning"]` |
| `position.longitude` | float, degrees, + east, nullable | `weather_current` | `call: WfbAstro.longitude`, same |

- `runtime-lib/WfbAstro.mc` (new): `latitude(conditions as Weather.CurrentConditions) as Float?`
  and `longitude(...)`: null when `observationLocationPosition` is null,
  else `toDegrees()`'s `[0]`/`[1]` as a `Float` (`Position.Location.toDegrees`
  returns `Array<Double>`; `Toybox/Position/Location.html`). Each function
  carries its own `has` check for the field and for `Toybox.Position` if the
  module can be absent on any installed device (check, do not assume), per
  `docs/lore/monkeyc.md` ("a barrel function needs its own check").
- `doc`: "latitude of the weather observation, degrees north; needs the
  Positioning permission, and is absent until the watch has a weather
  report". `source_ref`: `Toybox/Weather/CurrentConditions.html`. The
  manifest gains `Positioning` through `permissions` like `UserProfile`
  does today (check `ts/src/emit/manifest.ts` derives it; it is in
  `watchface_permissions`).
- Sample values: `51.4769`, `-0.0005` (the Royal Observatory, Greenwich —
  nobody's own, and it makes local sidereal time equal GMST).
- Research note `docs/research/39-position-and-astronomy.md`: the survey of
  the 34 installed devices (`observationLocationPosition` absent on
  `fenix5`/`fenix5x` only; `timeZoneOffset`, `Math.sin/cos/asin/acos/atan2`
  on all 34), the SDK's own words for each symbol with file paths and API
  levels, the permission rule ("If the app does not have the position
  permission then this will be null"), and what is UNVERIFIED on a watch
  (that a sideloaded face with `Positioning` actually receives the
  location; that `timeZoneOffset` includes DST). Slice D appends its
  formulas and accuracy to the same note.
- Guide: `docs/guide/data.md` gains a `position.*` paragraph with the
  permission and absence rules. `docs/limitations.md` §2's row on
  `catalog.Source.requires` ("set on no source") is updated if `requires`
  is used, else left.
- Tests: emitted code for a text bound to `position.latitude` (call, the
  `Weather` module guard on a mixed build with `fenix5`, the field guard);
  `api-gated` on `fenix5`; a real `./wfb build` of a scratch face on the
  three verification targets, warning-free, pasted in the report.

## 5. Slice D — `astro.*`, computed in `WfbAstro.mc` with a host twin

All through `call:` (4.1). Readers: `date_short` for the date, `clock` for
the time of day and `time.utc_offset`, `weather_current` where a position is
needed (those are nullable). Formulas: Meeus-style low precision, the same
arithmetic in `runtime-lib/WfbAstro.mc` and `ts/src/astro.ts` (the host
twin the preview and the lints evaluate), written so both round alike
(`Float` on the watch: say in the research note what precision that costs).

| Path | Type | Readers | Meaning |
|---|---|---|---|
| `astro.day_of_year` | number 1–366 | date_short | day of the year |
| `astro.julian_day` | float | date_short, clock | Julian day of the current instant, UT from `timeZoneOffset` |
| `astro.moon_age` | float days 0–29.53 | date_short, clock | days since the last new moon |
| `astro.moon_illumination` | float 0–1 | date_short, clock | illuminated fraction of the disc |
| `astro.equation_of_time` | float minutes | date_short | apparent minus mean solar time |
| `astro.sun_declination` | float degrees | date_short | the sun's declination |
| `astro.sidereal_time` | float hours 0–24, nullable | date_short, clock, weather_current | local mean sidereal time (GMST + longitude) |
| `astro.sun_altitude` | float degrees, nullable | date_short, clock, weather_current | the sun's altitude above the horizon now |
| `astro.sun_azimuth` | float degrees 0–360, nullable | same | the sun's azimuth, clockwise from north |
| `astro.sun_noon_altitude` | float degrees, nullable | date_short, weather_current | the sun's altitude at its culmination today |

- Accuracy targets, checked by tests against reference values (a few dates
  across the year; new and full moons of 2026; equinox declination ≈ 0;
  sun altitude at Greenwich noon on 21 June ≈ 62°): declination within
  0.3°, equation of time within 0.5 min, moon age within 0.3 d, altitude
  and azimuth within 1°. State the achieved figures in the research note.
- Every function has at most 9 parameters (`ts/test/parameter-limits.test.ts`),
  and the transcription test (`ts/test/barrel.test.ts`'s `STATEMENTS`
  style) holds key statements of `WfbAstro.mc` to the host twin.
- `wfb sources` groups them under `astro`; each `doc` says the formula's
  class and accuracy in a few words.
- Example `examples/features/astro/face.yaml` ("Feature Astro"): a
  dial showing every `astro.*` and `position.*` reading as text plus one
  needle gauge on `astro.sun_altitude`, warning-free on the three targets,
  lint-clean, previewed. Its goldens are the one allowed golden addition of
  this slice; the orchestrator regenerates them.
- Guide: a new "Astronomy" section in `docs/guide/data.md` with the table,
  the absence rule (position-dependent values are absent until a weather
  report with a location arrives), and the UNVERIFIED-on-a-watch note.
  `docs/lore/codegen.md` gains a bullet on `call:`/`extra_readers`. ADR 0005
  gets a dated amendment: computed sources are catalogue entries read
  through a named barrel call, never an expression-language function.
- Real build of the example on the three targets, warning-free, output in
  the report; `--build-stats` figure for the example.
